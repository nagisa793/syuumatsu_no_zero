# 音声入力の継続と復旧（v62）

## 修正した問題

- 戦闘終了・再戦がマイクを停止し、入力途中の言葉を消していた。
- 別画面への切り替えでマイクをオフにしたまま、戻っても再接続していなかった。
- 音声認識の「話し中」フラグが残ると、停止した接続を復旧できなかった。
- iPhoneの入力ストリーム準備を待ち続けると、認識開始も止まっていた。
- 接続の一時中断を、接続ボタンの押し直しが必要なエラーとして扱っていた。
- 音声結果のコールバック内で技を解釈・実行していた。

## 実装

マイクの有効状態はプレイヤーのボタン操作で管理する。ゲームのリセット・結果画面・技の使用では停止しない。ブラウザが画面を隠したときは接続を中断するが、有効状態と未確定の言葉は保持し、戻ったときに再接続する。

認識開始はiPhone用の補助入力ストリーム準備から独立させた。入力トラックの終了、長時間のミュート、認識の接続終了・一時エラーを検出して再接続する。許可拒否は繰り返し再試行せず、未確定の言葉を残して許可後の再接続を受け付ける。

結果を受け取ったら第一候補の文字列をそのまま保持する。発声した「エンター」で確定した指示を実行キューへ渡し、別のタスクで順番に処理する。語句補正は実行時にだけ行う。実行中の例外を捕捉して失敗した指示を破棄し、次の音声受付を継続する。ゲームの更新はマイク有効中に時間予算を設け、遅延を取り戻す処理でイベント処理を占有し続けないようにした。

## 検証

`node tests/battle.cjs` で実際のゲームコードに模擬認識イベントと模擬入力トラックを送り、初回起動・許可待ち・再戦・勝敗・一時停止・画面復帰・オートモード・途中入力・再接続・トラック終了とミュート・指示実行例外・複数指示の順次実行を検証した。既存の戦闘・アニメーション・音楽の回帰テストも実行した。

物理マイク、iPhone実機、認識サービスの通信品質はこのテストでは確認できない。ブラウザが認識結果を返さない音声を復元する機能ではなく、ゲーム側の停止条件・待機・処理占有・エラーで受付が止まる原因を修正したもの。録音や新しい音声送信処理は追加していない。
